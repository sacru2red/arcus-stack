# ARCUS Work Loop (`arcus-work-loop`)

Execute the task autonomously in an iterative implementation-and-verification loop from discovery through verified completion without stopping prematurely or leaving half-finished stubs.

## Execution Loop

1. **Resolve or Self-Seed the Task Checklist (4-Tier Discovery — Never Abort If Missing)**:
   - **Domain Grounding First**: If `ONBOARDING.md` (or `CONTEXT.md`) exists in the workspace, consult it first so your implementation respects domain-to-code mappings, business invariants, authz tiers, and legacy red-line minefields (verifying cited code paths against live code).
   - **Role Boundary Note**: [`./references/work-loop-checklist.md`](./references/work-loop-checklist.md) is this skill's **meta sign-off rubric**, NOT the user's project task file. Never abort or exit the loop claiming you "could not find the checklist document on disk."
   - Resolve the active **Task Checklist** using this strict 4-tier priority order (a candidate from Tiers 1–3 is valid **only if** it matches the current task goal AND has at least one remaining unchecked `- [ ]` item not yet landed in subsequent turns or `git log`; otherwise immediately fall through to the next tier):
     1. **Tier 1 (Explicit Path or Inline Prompt)**: If the user's message includes `- [ ]` items inline or names a plan/checklist file path on disk that exists and has pending `- [ ]` items for this goal, adopt those items (and their paired `➔ Verify:` lines). If the named file does not exist on disk or has 0 pending `- [ ]` items, never abort—fall through to Tier 2.
     2. **Tier 2 (In-Conversation `arcus-plan` Output)**: Scan earlier messages in the current conversation for the most recent [`arcus-plan`](../arcus-plan/SKILL.md) *(when co-installed)* or `arcus-review` Plan v2 checklist (`## 3. Actionable Execution & Verification Checklist`). Adopt its unchecked `- [ ]` items (together with any indented `- ➔ **Verify**:` sub-bullets) **only if** that plan targets the current user request and its steps were not already completed in later turns (skipping any optional `DECISIONS.md` item unless explicitly authorized by the user). If earlier chat checklists belong to a previous completed task, fall through to Tier 3.
     3. **Tier 3 (Workspace Plan / Task Files)**: If running in a fresh thread or post-handoff with no matching in-chat checklist, check the workspace for an active plan document (`PLAN.md`, `TODO.md`, `TASKS.md`, or `.audit/*.md`). Adopt it **only if** its target files/goal match the current request and it contains at least one unchecked `- [ ]` item not yet committed in `git log` (never hijack a general project roadmap backlog in `TODO.md`, a stale `.audit/*.md` artifact from an unrelated task, or an already-finished all-`[x]` plan—fall through to Tier 4 instead).
     4. **Tier 4 (Mandatory Self-Seeding Fallback — Never Bail Out)**: Whenever Tiers 1–3 yield 0 matching unchecked `- [ ]` items, **never stop, never exit with 0 edits, and never ask where the checklist document is**. Perform a fast parallel discovery of the relevant codebase files/tests, construct a concrete 3–7 step `- [ ]` execution & verification checklist yourself per [`checklist.md`](../arcus-mode/internal/checklist.md) *(when co-installed)* (registering the steps in your session's step tracker such as `update_steps` / `TodoWrite` when available), and immediately proceed to Step 2.
2. **Minimal, High-Precision Implementation**:
   - Work through the checklist systematically, following existing codebase conventions, types, and module boundaries.
   - For HTML/CSS or client-side JS/DOM changes, consult `npx -y modern-web-guidance@latest search "<2-5 word query>"` and `retrieve "<id>"` (falling back to `npx --offline -y` or skipping non-blockingly if offline) before writing custom UI or DOM workarounds.
   - For TypeScript, domain naming, or stateful query and mutation changes, follow [`typescript-best-practices.md`](../arcus-mode/internal/typescript-best-practices.md) *(when co-installed; inline fallback: verify domain meaning over UI copy, follow active repo grammar not legacy pockets, infer locals and annotate boundaries, prefer `satisfies` and generics over forced assertions or repeated callback types, separate `null`/`undefined`/`""`/`0` per domain, default to immutable `const` transforms without mutable `Set`/`Map` defaults, and centralize duplicate queries or mutations under one owner)*.
   - For live database schemas, persisted queues or caches, data backfills, or rolling-deploy wire contracts, follow [`safe-migration.md`](../arcus-mode/playbooks/safe-migration.md) *(when co-installed; inline fallback: never ship destructive or blocking DDL or combine Expand and Contract in one PR; use online/`CONCURRENTLY` DDL, dual-read and dual-write with `N-1`/`N` rollback safety, chunked idempotent throttled backfills with parity checks, and defer Contract cleanup to a separate follow-up PR)*.
   - For backend services, DB queries, transactions, or outbound RPC/HTTP changes, follow [`backend-reliability.md`](../arcus-mode/internal/backend-reliability.md) *(when co-installed; inline fallback: bound list queries and eliminate N+1 loops, inspect query plans or indexes on hot tables, keep external I/O out of DB transactions with idempotency keys across boundaries, require explicit timeouts and cancellation with bounded jittered retries only for transient faults on idempotent operations, enforce rate limits or backpressure, and emit structured correlation-ID logs without PII or secrets)*.
   - Never apply symptom patches (e.g., swallowing errors, arbitrary timeouts, blind null checks). Fix the underlying logic.
   - If new requirements or edge cases surface mid-task, update the checklist dynamically so nothing is forgotten.
3. **Self-Diagnostics & Guarded Repair**:
   - Immediately run each item's verification check (typecheck, linter, unit/integration tests, build) after editing.
   - Mark an item `- [x]` **only** after its verification check passes with real evidence. If a check fails, diagnose the root cause and fix all reported issues before re-running.
4. **Evidence-Gated Completion & `arcus-explain` Briefing**:
   - Audit your final state against [work-loop-checklist.md](./references/work-loop-checklist.md).
   - For visual UI changes (especially after [`arcus-ui-propose`](../arcus-ui-propose/SKILL.md) *(when co-installed)*), capture a fresh post-polish `.audit/ui-propose/<task-slug>/99-after-final.png` matching `00-before.png`'s route, viewport, scroll position, and light or dark theme after checks pass, and verify `git diff --cached --name-only` stages zero `.audit/` PNGs before commit.
   - Present the completed checklist (`- [x]`) alongside the concrete verification evidence (commands run and their outputs).
   - Immediately after the verification evidence (and before any optional `DECISIONS.md` prompt), include a concise **Completion Briefing** following [`arcus-explain`](../arcus-explain/SKILL.md) (when co-installed). *Inline fallback & Output Hygiene*: Calibrate the depth internally to a 20-something SW/CS graduate (decode repo-specific domain jargon into standard CS mental models without childish analogies or architectural fluff), **never echo the internal persona label (`20s CS Grad` / `20대 SW 학과 졸업생...`) in the output heading or text**, and **localize the heading and all 4 bullet labels into the user's conversation language** (e.g., Korean: **핵심 요약**, **구조 및 동작 모델**, **동작 원리 및 트레이드오프**, **적용 효과 및 검증 기준**; English: **Core Essence**, **Mental Model**, **Mechanism & Trade-offs**, **Impact & Verification**).
   - If a new architectural decision was made during the loop and the workspace has not opted out of `DECISIONS.md`, propose recording `D-xxx` (or opting out) in your final handoff turn—never pause the loop mid-flight to ask.
