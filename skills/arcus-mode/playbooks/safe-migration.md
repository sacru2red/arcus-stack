### Safe migration

**Expand first, backfill and verify in production, then contract in a separate PR. Never ship Expand and Contract in one deploy.**

This playbook overrides single-wave cutover in [refactoring.md](./refactoring.md) and **principle-migrate-callers-then-delete-legacy-apis** whenever live databases, persisted storage, or mixed-version nodes are involved. Internal code-only refactors with no persisted state or rolling-deploy callers stay on [refactoring.md](./refactoring.md).

1. **Check scope and DDL lock safety.** Trigger this playbook whenever a change touches a live database schema, a persisted queue or cache payload, or a rolling-deploy external API or event wire contract. Forbid single-PR destructive or table-locking DDL: `DROP COLUMN`, `RENAME COLUMN`, table-rewriting `ALTER TYPE`, `SET NOT NULL` full-table scans without `CHECK (...) NOT VALID` followed by `VALIDATE CONSTRAINT`, and blocking `CREATE INDEX` without `CONCURRENTLY` or online DDL. Bound every migration statement with explicit `lock_timeout` and `statement_timeout` limits so lock contention fails fast instead of queueing live traffic.
2. **Ship PR A to expand and dual-write.** Add the new nullable column, table, or wire field alongside the old shape using non-blocking DDL. Update readers to accept both old and new shapes and fall back to the old shape when the new field is absent. Update writers to dual-write both shapes on every write path. Verify that `N-1` old nodes and `N` new nodes interoperate cleanly in both directions, including an immediate rollback from `N` to `N-1`. Merge and deploy PR A before starting any backfill or touching legacy reads.
3. **Backfill in bounded chunks and verify parity.** Backfill historical rows or persisted entries in bounded key-range chunks rather than one full-table update. Write idempotent updates (**principle-make-operations-idempotent**) so retries and restarts converge to the same state. Throttle batch size and inter-batch pauses so WAL volume and replication lag stay within production budgets. Verify row counts, null counts, and domain invariant parity between the old and new shapes (**principle-prove-it-works**). Re-confirm `N-1` and `N` rollback safety before modifying old read paths.
4. **Ship PR B to contract in a separate follow-up PR.** Wait until 100% of nodes run release `N`, parity checks pass, and the rollback bake window clears. In a separate follow-up PR, switch reads exclusively to the new shape, stop writing the legacy shape, and remove the dual-write shim. Drop legacy columns, tables, constraints, or deprecated wire fields only after no live node reads or writes them (**principle-sequence-verifiable-units**). If dropping storage still risks racing with in-flight readers, split read cutover and `DROP COLUMN` into separate deploys. Keep PR A and PR B as separate PRs across every migration phase. Run **Opening a PR**.

**Reply:** the migrated schema or wire boundary, DDL lock-safety checks, PR A expand and dual-write scope, chunked backfill and parity verification plan, bake-window exit criteria, and deferred PR B contract scope.
